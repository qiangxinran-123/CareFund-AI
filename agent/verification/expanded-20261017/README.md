## 检查与调用规则

本批直接调用现有已发布 Dify 应用，模型配置沿用 `deepseek-flash`，未改变线上提示词、参数、生产 Python 代码或共享契约。密钥通过匿名进程管道传入，不写入脚本、命令行、状态文件或报告。无自动重试、无模拟降级，每个案例至多调用一次；遇到失败或内容标记立即暂停。若人工确认是扫描器误报，必须另存响应哈希及裁决，保留原标记，只续跑未尝试案例。

所有请求先校验；草稿不满足确认、问题列表等前置条件时在网络前阻止。保存的响应再经过正式 AgentService，包括 Schema、身份／revision、事实保留、证据引用、新字段范围、候选状态与确认、草稿逐条内容检查。抽取补充检查疾病与分期、关系、金额及角色、来源、不确定性、追问数量和已知平台／审批措辞。部分场景另作上下文复核；这些不是完整语义或临床真实性核验。

草稿只做固定逐条排版，注入案例中事实原文可能作为引述保留，不能因此当作可直接发布文案。真实来源均为最小疾病短语，不包含本批压力案例中的虚构费用、日期或冲突材料。

实际 D 回放使用现有独立本地代码和演示 policy，将通过 A 的抽取响应映射为 ValidationRequest，检查双方契约、版本、问题引用与输入未被修改。草稿不混入抽取回放计数。共享 6 份 Schema 比较解析后的 JSON 内容，不能将 CRLF／LF 字节差异误认作业务契约不同。演示 policy 不是团队批准的生产配置，也不是 B/D 在线全流程。
