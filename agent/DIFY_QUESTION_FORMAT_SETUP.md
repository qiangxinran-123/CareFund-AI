## 处理范围

现有 SYSTEM 已明确：没有团队提供的必填规则时，追问 required=false。新代码节点仅落实这一条已有政策：当一个结构完整的追问只缺 required 时，补布尔值 false。已存在的 true/false 原样保留，错误类型（如字符串 "false"）直接拒绝。将来团队定义必填规则时，必须一起更新这项政策，不能继续套用默认可选。

病情、金额、来源、证据、核验及确认状态等内容不由此节点补造。非法 JSON、缺少其他追问字段或事实元数据仍失败。正式 AgentService 对完整输出的契约、引用和业务范围检查继续执行；这个节点不替代 A/B/D 校验，也不证明医疗内容正确。

每次输出保留三个字符串：

| 名称 | 内容 |
|---|---|
| result | 供 A 使用的 JSON 字符串 |
| raw_result | 模型原始文本 |
| normalization_report | 处理版本及补 false 的字段路径，不含病情 |

评测器已准备核对原文、处理记录与 result 是否一致，并单独记录原始模型是否通过契约、哪些结果依赖程序处理，不能把后者算作模型原始结构正确。

## 在现有 Dify 抽取应用中安装

使用原来的「CareFund-信息抽取与追问-修订版」应用，这样继续使用原应用密钥。

1. 进入「编排」，新增「代码执行」节点，命名为「追问可选标记与原文留存」，语言选 Python3。把它放在 LLM 与「输出」之间。
2. 在新节点添加输入变量 `llm_text`，值选择原 LLM 的 `text` 输出。
3. 打开同目录的 `dify_question_format.py`，复制全部内容，替换新代码节点中的示例代码。
4. 为新代码节点声明三个输出变量，类型全部选 String：`result`、`raw_result`、`normalization_report`。
5. 连线改为「开始 → LLM → 追问可选标记与原文留存 → 输出」，移除 LLM 直接到「输出」的旧线。
6. 在最后的「输出」节点，把 `result` 的值改为新代码节点的 `result`；再添加 `raw_result` 和 `normalization_report`，分别选择代码节点的同名输出。不要把字符串改成 Object。
7. LLM 和代码节点的失败自动重试均保持关闭，代码错误按失败终止，不配置默认成功结果或继续执行。点击「发布」。
