## 本次范围

本次使用 raw_data.csv，不下载图片、不读取 pickle、不训练模型。原始 CSV 和含完整叙述的规范化请求只存放在被 Git 忽略的 agent/.local/mdcc/，不纳入此前的 A 模块交付 ZIP，也不直接发送给 Dify。

先验证 Zenodo 公布的 CSV MD5：563084b6ff62078dc3dead2e55ff71a7。下载未完整或校验不符时不生成正式测试报告。

三个层次必须分开统计：

1. 原始记录的本地请求适配：默认200条医疗类原文，检查能否组成正式 AgentExtractRequest。此项不调用模型，不代表抽取准确率。
2. 最小匿名摘录：从不同记录中按词典匹配至多30条“I/My mother…was diagnosed with…”短句，仅保留代词/亲属关系、诊断措辞和常见疾病词。排除源句含否定、疑似、缓解等风险标记的匹配；不发送姓名、地址、日期、筹款目标、已筹金额、项目 ID 或全文。它是有选择和上下文裁剪的摘录测试，不能代表原始长文本表现，也不证明诊断真实。
3. 明确虚构的压力案例：20条抽取、10条草稿，覆盖已支付/预估费用、筹款金额误用、美元及币种未知、未确诊与否定诊断、不完整日期、夹带指令、旧事实保留、材料费用冲突和逐条成稿。这些是本项目构造，不能计作30条之外的真实 MDCC 标注。

词典与关系/疾病关键词检查是部分自动判据，未形成完整人工金标准。必须保留失败及待复核项，不将“JSON合法”当成事实正确。不完整上下文、否定漏检及中文别名覆盖不足仍是限制。筹款目标、已筹款和捐款不是已支付医疗费，也不能作为医疗费用标准答案。

## 运行

在团队仓库根目录、正式 contracts/ 和本地 .venv 已准备时：

```powershell
.\.venv\Scripts\python.exe -m agent.mdcc_prepare --csv agent/.local/mdcc/raw_data.csv --sample-size 200
.\.venv\Scripts\python.exe -m unittest discover -s agent/tests -q
.\.venv\Scripts\python.exe -m agent.batch_check --gui
```

第一步核对文件指纹，生成本地 profile、200条原始请求、摘录来源记录及最多60条模型测试用例；不调用 API。batch-cases.json 是后续模型输入的本地审查材料。real-records-local-only.jsonl 不被批量调用器接受。

第二步中的网络为模拟，不计入真实测试。第三步需分别填写抽取应用及新草稿应用的密钥；密钥仅驻留进程内存，程序不保存、不从聊天读取。模型输入只发送规范化 request，不发送本地 provenance、CSV 或完整原始请求。

真实调用没有自动重试；HTTP/网络/模型协议错误立即停止，连续三次边界拒绝停止；语义判据失败保留记录并继续剩余案例，避免只挑成功结果。每条只尝试一次。可用 --operation extract/draft、--limit 数量限制单次范围，默认最多100条，本次预备用例最多60条。暂停或重跑应先查看已有调用记录，避免重复消耗。

批量状态位于 agent/.local/mdcc/batch-live-status.json。preparation-report.json 仅是本地准备结果；只有状态报告出现真实逐条返回才可报告模型测试完成。语义失败响应仅在通过正式边界校验后保存，并明确标为 automatic_checks_failed，不作为通过样本。
