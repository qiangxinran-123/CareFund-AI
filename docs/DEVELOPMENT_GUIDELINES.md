# CareFund-AI 参赛开发规范

适用赛事：第九届传智杯全国大学生数智创新与 AI 应用大赛——AI WEB 网页开发挑战赛。

作品提交截止为 2026 年 11 月 18 日。提交前以稳定、可解释、可演示为优先级，不再引入未经完整测试的大型依赖或与核心流程无关的功能。

## 开发原则

1. AI 必须是申请资料抽取、追问和草稿生成的核心能力，而不是装饰性 API 调用。
2. Web 前端是主要展示入口；后端用于材料处理、AI 编排、持久化和安全门禁。
3. 不得编造病情、诊断、治疗经历、日期、费用、材料或审核结论。
4. 模型输出只能作为候选结果，必须经过 Schema、引用、冲突、确认和 revision 校验。
5. 涉及用户数据时遵循最小收集、脱敏展示、本地优先处理和密钥隔离原则。
6. 所有功能变更同步更新契约、测试和面向评审的说明。

## 模块职责

- `frontend/`：用户流程、AI 状态反馈、问题展示、草稿确认和错误边界。
- `backend/`：REST API、OCR、SQLite、任务编排、状态机、并发控制和导出。
- `agent/`：LLM 输入输出、事实抽取、补充问题和受事实约束的草稿。
- `validation/`：证据引用、字段完整性、冲突、严重性和阶段门禁。
- `contracts/`：所有模块共享的 OpenAPI 与 JSON Schema。

## Git 与代码质量

- 保留真实、可审查的提交历史；一个提交解决一个清晰问题。
- 提交信息描述结果，禁止提交密钥、真实患者资料、构建产物和本地数据库。
- 修改公共字段时同时更新 Schema、OpenAPI、示例、前后端类型和测试。
- 合并前至少执行相关单元测试、类型检查和生产构建。
- 注释解释安全约束和非显然决策，不保留过期交接记录、临时比赛编号或已失效待办。

## 验收底线

- 真实模式完成“填写申请—上传材料—OCR—AI 分析—校验—草稿—确认—导出”。
- Mock 模式有明确标识，失败时不得伪装成真实服务成功。
- 所有阻断问题都无法通过删除提示 ID、客户端改状态或使用旧 revision 绕过。
- warning 与 info 仍完整展示和导出，不因允许继续而丢失审计记录。
- 评审演示所用数据均为虚构或充分脱敏的数据。
